# tyche Audit Report — 2026-09-25

**Scope:** the whole repository outside vendored `lib/`: `src/`, `tests/`,
`dist/`, CI, and every document. **Baseline:** 1.0.3 (commit `48e8426`, cyrius
6.6.6). **Result:** 1.1.0.

## Executive summary

tyche's frozen contract is *"same seed, same bits, on every target"*. It did not
hold for `rng_normal`, and nothing could have noticed. The function called the
`f64_ln` builtin, which cyrius lowers to x87 on x86_64 but to a software polyfill
on aarch64 that is up to 213 ulp off, so about a third of aarch64 normal draws
differed from x86_64. The test suite was statistical only, so no change to any
stream could fail it; CI ran on x86_64 alone; and the fuzz and benchmark files
were scaffold stubs. 1.1.0 fixes the contract (tyche now computes a correctly
rounded `ln` itself), pins the stream with exact-bit test vectors from an
independent reference implementation, runs them on aarch64 in CI, and brings the
documentation back in line with the code.

No security vulnerability was found. The threat surface is unchanged: no I/O,
no parsing, no allocation, and the not-a-CSPRNG boundary is intact.

## Method

- **Toolchain sweeps:** `cyrius audit` (fmt / lint / docs / tests / bench),
  `cyrius coverage`, `cyrius doc --check`, `cyrius deny`, `cyrius vet`,
  `cyrius lint --strict-deferrals`, `cyrius deps --verify`.
- **Manual review** of every non-vendored file.
- **Cross-target stream dumps:** raw bit patterns from x86_64, and from aarch64
  under qemu-aarch64 11.1.1, diffed byte for byte (a 1,952-line golden dump and
  10,000,000 consecutive `rng_normal` draws).
- **Correctly rounded reference:** Python `decimal` at 50 digits, used to check
  `ln` on 1,294,808 inputs and to generate the known-answer vectors.
- **Mutation testing** of the new suite and fuzz harness.
- **Downstream:** every consumer's own suite, run with its pinned tyche and then
  with 1.1.0, each under its own pinned cyrius (6.6.2).

## Stream impact of 1.1.0

`rng_seed`, `rng_u64`, `rng_uniform` and `_rng_state` are bit-identical to 1.0.3.
For `rng_normal` on x86_64, 1,081 of 10,000,000 draws (0.0108%) moved: 959 by
1 ulp, 121 by 2 and one by 3. Recomputing all 10,000,000 draws with a correctly
rounded `ln` matched 1.1.0 on 9,999,999 of them, and matched 1.0.3 on none of
the 1,081 that changed. So every change is an x87 misrounding. The one draw
where 1.1.0 differs from the correctly rounded stream is a hard case that x87
rounded the same way, so it is unchanged from 1.0.3. aarch64 now produces the
x86_64 stream.

## Observations — not changed, and why

- **`rng_normal` is 3.8× slower** (92 → 347 ns). This is the cost of a correctly
  rounded `ln` from basic ops under cyrius's code generation. Alternatives are
  costed in `docs/benchmarks.md`; a faster `_rng_ln` is on the roadmap, with the
  acceptance bar of identical bits.
- **`dist/tyche.deps` still lists ten stdlib modules**, though the library needs
  none since 1.1.0. Trimming it could change how consumers' `cyrius deps`
  resolves; it does no harm as it is.
- **xorshift64 is F2-linear.** Per the literature, plain xorshift generators
  fail BigCrush's MatrixRank and LinearComp tests (Vigna, 2016, *An experimental
  exploration of Marsaglia's xorshift generators, scrambled*, ACM TOMS 42(4));
  this audit did not re-run TestU01. The algorithm is frozen and documented as
  statistical-only; `rng_uniform` uses the top 53 bits.
- **`rng_normal` discards the polar method's second variate.** This is
  deliberate: caching it would add hidden state beside `_rng_state`, breaking the
  checkpoint contract, and would change the stream.
- **`_rng_ln` has a precondition, not guards.** It is internal, and its only
  caller passes `s` in `[2^-104, 1)`.
- **`src/test.cyr` is a no-op `[build].test` entry.** It is harmless and
  documented; `cyrius test` also runs `tests/*.tcyr`.
